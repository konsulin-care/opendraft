# Protocol Versioning

**Normative.** Defines how OpenDraft protocol revisions are identified, recorded, and retrieved as immutable artifacts.

## 1. Revision Model

Every protocol revision is described by four fields:

| Field | Value | Notes |
|-------|-------|-------|
| `name` | `opendraft` | Fixed constant. |
| `version` | Full 40-character Git commit SHA | Equals `commit` (ADR-007). |
| `repository` | `https://github.com/konsulin-care/opendraft` | Canonical constant; single source of truth, mirrored in `scripts/protocol-manifest.ts`. |
| `commit` | Full 40-character Git commit SHA | The exact revision that defines the artifacts. |

Rules:

- `version == commit`: the protocol version is the commit. No tags, branches, or short SHAs are used as identifiers (ADR-007).
- The full commit SHA is mandatory for immutable provenance.
- `name` and `repository` are fixed; `version`/`commit` change only when protocol artifacts change.

The model is recorded in two places:

1. `protocol/protocol.manifest.json` — the `protocol` block (generated by `mise run update-protocol-manifest`).
2. Publications — the `od:protocolRevision` property records the commit (see [ADR-015](../docs/ADR/015-protocol-reproducibility.md)).

## 2. Deriving the Commit

The revision is derived from artifact history, not the repository tip:

```bash
git rev-list -1 HEAD -- ':(glob)protocol/**/*.ttl'
```

- Only `.ttl` artifacts under `protocol/` define the revision.
- Documentation-only and CI-only changes (`.md` files, `.github/`, tooling) never bump the revision.
- The generator (`scripts/protocol-manifest.ts`) and the verifier (`mise run verify-protocol`) both encode this rule.

## 3. Canonical Repository

The canonical repository constant is:

```
https://github.com/konsulin-care/opendraft
```

It is the single source of truth for:

- the manifest `repository` field,
- the project template's `protocol.repository` field,
- every immutable artifact URI (below).

## 4. Artifact URI Conventions

Immutable references address artifacts by commit. With `<sha>` a full 40-hex commit, the three canonical forms are:

- **Repository at commit** — the entire repository at the revision:

  ```
  https://github.com/konsulin-care/opendraft/tree/<sha>
  ```

- **Directory at commit** — the protocol directory at the revision:

  ```
  https://github.com/konsulin-care/opendraft/tree/<sha>/protocol
  ```

- **File at commit** — a single artifact as raw content:

  ```
  https://raw.githubusercontent.com/konsulin-care/opendraft/<sha>/protocol/opendraft.ttl
  ```

For example (revision `22fa25b9fbb526f388ae4892f6294a52e6961db9`):

```
https://raw.githubusercontent.com/konsulin-care/opendraft/22fa25b9fbb526f388ae4892f6294a52e6961db9/protocol/article.shacl.ttl
```

## 5. Non-Immutable References

The following are **not** immutable and must not be used as protocol identity pointers:

- Branch URLs (`/tree/master`, `/tree/main`) — point at whatever the branch names today.
- `HEAD` — moves with every push.
- Tags — can be moved or repointed without changing artifact identity (ADR-007: tags are not identifiers).
- Short SHAs — not collision-proof, insufficient for provenance.

## 6. Repository Relocation

If the canonical repository moves (for example, to a new hosting org), adapt as follows:

1. Update the canonical constant in `scripts/protocol-manifest.ts`.
2. Run `mise run update-protocol-manifest` to regenerate the manifest and project template.
3. Update this section and note the move in the manifest `generatedBy` history (if any).

Relocation is low-risk by design: integrity is anchored in `commit` plus per-artifact hashes, and `repository` is a *locator*, not an identity. Existing revisions remain verifiable after the move.
